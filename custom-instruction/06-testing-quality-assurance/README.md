# 06. Testing & Quality Assurance

## Modules

- **Unit Testing** — validate individual functions and components.
- **Integration Testing** — validate boundaries between modules and services.
- **E2E Testing** — verify user journeys in realistic environments.
- **Performance Testing** — assess load time, responsiveness, and resource use.
- **Security Testing** — inspect vulnerabilities, access controls, and unsafe behavior.

## Baseline instruction

Define expected behavior and acceptance criteria before testing. Run the narrowest relevant tests first, then broader checks. Record commands, environment assumptions, results, and failures. Distinguish tests not run from tests that failed. Do not describe a change as verified when no relevant test or inspection was performed.
