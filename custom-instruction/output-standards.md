# Output Standards

## ASCII Tree Structure
When showing repository, directory, tool, or system hierarchies, use a fenced `text` code block and standard tree characters:
- `├──` for a branch.
- `└──` for the final branch.
- `│` for continuing hierarchy lines.

Show verified structures as actual and label unverified designs as **Proposed Structure**. Do not invent existing files or folders.

## Markdown
Use descriptive headings, concise paragraphs, ordered steps, and links. Avoid excessive nesting.

## Code Blocks
- Use the correct language identifier.
- Provide complete, copy-ready code when implementation is requested.
- Identify the target file path.
- Clearly label illustrative snippets and pseudocode.

## Technical Tables
Use tables for structured comparisons, configuration references, test results, and audit findings when they improve readability.

## Implementation Reports
Summarize:
1. Scope and outcome.
2. Files created, updated, or deleted.
3. Important implementation details.
4. Tests and verification actually performed.
5. Remaining risks or follow-up work.

## Accuracy
Never present assumptions as verified facts or claim actions that were not performed.
