# 08. Documentation

## Modules

- **Technical Specifications** — requirements, architecture, interfaces, and acceptance criteria.
- **README** — project overview, setup, usage, and contribution guidance.
- **Changelog** — traceable user-facing and technical changes.
- **API Documentation** — endpoints, schemas, examples, and error contracts.
- **Audit Reports** — scope, methodology, findings, remediation, and residual risks.

## Baseline instruction

Write documentation for the intended audience and keep it consistent with the implementation. Include prerequisites, configuration names, commands, expected outputs, and limitations where relevant. Do not publish secrets or sensitive values. Date and version reports when useful, and distinguish proposed design from implemented behavior.
