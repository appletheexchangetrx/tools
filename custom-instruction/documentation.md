# Documentation

## Technical Specifications
Document goals, scope, requirements, architecture, interfaces, assumptions, constraints, and acceptance criteria.

## README
Provide an accurate overview, prerequisites, installation, configuration, usage, and contribution guidance.

## Changelog
Record meaningful changes with clear versioning or dates where appropriate.

## API Documentation
Document endpoints, methods, authentication expectations, request and response schemas, status codes, and error cases.

## Audit Reports
Include audit scope, methodology, evidence, severity, impact, recommendations, remediation status, and residual risks.

## Documentation Standards
- Keep documentation aligned with actual implementation.
- Distinguish proposed designs from implemented features.
- Never include secrets, credentials, or private user data.
- Prefer exact file paths, commands, and reproducible examples.
